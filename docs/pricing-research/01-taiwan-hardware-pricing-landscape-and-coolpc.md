# 第一章：台灣電腦零組件定價生態系與「原價屋」資料結構剖析

---

## 1.1 台灣電腦 DIY 通路生態與定價話語權

在台灣消費級個人電腦（DIY PC）市場中，電腦硬體零件的終端售價存在一個高度集中且公開透明的「定價錨點 (Pricing Anchor)」生態：

```
                      【台灣電腦 DIY 零件定價拓撲】
  
  ┌────────────────────────────────────────────────────────┐
  │ 上游原廠 / 晶片商 (Intel, AMD, Nvidia, ASUS, MSI, 技嘉)  │
  └──────────────────────────┬─────────────────────────────┘
                             │ 代理商分銷 (聯強、捷元、展碁)
  ┌──────────────────────────▼─────────────────────────────┐
  │ 核心價格錨點 (Pricing Anchor)                           │
  │ ★ 原價屋 CoolPC (涵蓋全台實體報價標竿、現金含稅、透明看板)│
  │ ★ 欣亞數位 Sinya (排排購、組合價與促銷搭售競爭者)       │
  └──────────────────────────┬─────────────────────────────┘
                             │ 市場參照外溢
  ┌──────────────────────────▼─────────────────────────────┐
  │ 綜合電商與第三方比價 (PChome 24h, momo, 蝦皮, 露天)      │
  │ • 通常受限於平台抽取 5%~10% 手續費，單品常高於原價屋報價 │
  │ • 透過滿額折價券、信用卡回饋形成動態博弈              │
  └────────────────────────────────────────────────────────┘
```

### 為什麼「原價屋 (CoolPC)」是全台定價基準？
1. **全台單品價格統一透明**：原價屋打破了早期光華商場各店家看人喊價的陋習，推行「線上即時估價單、全省門市同價、現金含稅附發票」機制，促使全台玩家與零售門市均以其報價作為公認市價標竿。
2. **規格分類最全面**：其線上估價系統細分超過 30 個類別（處理器、主機板、顯示卡、記憶體、固態硬碟、電源供應器、散熱器、機殼等），每天隨時更新促銷與缺貨狀態。
3. **「搭機價」與「限組裝」市場機制**：在顯卡荒或熱門 CPU 缺貨期，原價屋開創了「限搭整機」、「促銷組合價」的定價規則，成為觀察零件供需張力的第一線晴雨表。

## 1.2 官方是否有公開 API？官方態度與商業壁壘

針對使用者常詢問「原價屋是否有官方 API 可以直接呼叫？」：

> ### 🛑 事實裁決：【完全沒有官方公開 API】
> * 原價屋官方**從未提供、也未曾規劃任何公開的 RESTful、GraphQL 或 JSON API** 供外部開發者免費調用。
> * 欣亞數位（Sinya）亦同，其線上估價系統僅供終端消費者瀏覽下單，無對外開放資料介面。

### 為什麼官方不開放 API？
1. **防範自動化惡意爬蟲負載**：原價屋伺服器長年承受極高流量，若開放免驗證 API，極易遭爬蟲高頻輪詢（Polling）導致資料庫或 Web 伺服器崩潰。
2. **保護商業報價競爭優勢**：即時報價涉及與代理商簽署的促銷協議與競品防禦，不希望競爭對手毫無阻礙地透過自動化腳本執行「低 1 元攔截定價策略」。
3. **商業流程需要人工確認**：原價屋的線上估價單本質上是「詢價與暫存單」，真正下訂後必須由門市客服人員進行人工電聯確認庫存與規格相容性，並非無人化的標準電商購物車。

## 1.3 原價屋估價系統 (`evaluate.php`) 的資料結構逆向

雖然沒有官方 API，但原價屋的報價資料在客戶端是公開可見的。解析其網頁結構可發現其技術特徵：

### 1. 網頁渲染架構
- **伺服器端渲染 (SSR)**：造訪 `https://coolpc.com.tw/evaluate.php` 時，伺服器直接輸出包含全量零件清單的巨大 HTML 頁面（檔案大小通常在數百 KB 至 1 MB 以上）。
- **DOM 封裝形式**：所有零件依照類別封裝於各個 `<select>` 下拉選單之中，每個零件作為一個 `<option>` 節點。

### 2. 資料非結構化痛點（"String Soup" 字串雜燴）
原價屋資料最大的解析挑戰在於其**「字串高度非結構化」**。以顯示卡為例，單一 `<option>` 的文字內容通常長這樣：

```text
微星 RTX4060 VENTUS 2X BLACK 8G OC(2490MHz/19.9cm/雙風扇/註四年) 促銷搭機價 $8990
```

這行字串在沒有分欄的情況下混雜了十餘種屬性：
- **品牌商**：微星 (MSI)
- **核心晶片**：Nvidia GeForce RTX 4060
- **系列名稱**：VENTUS 2X BLACK
- **顯存容量**：8G GDDR6
- **出廠頻率**：OC (超頻版, 2490MHz)
- **卡身物理長度**：19.9cm (影響機殼相容性)
- **散熱規格**：雙風扇
- **保固條件**：線上註冊四年保固
- **特定限制**：促銷搭機價（不可單買）
- **終端定價**：NT$ 8,990 元

### 3. 解析技術演進：Regex vs 語意萃取
傳統開發者使用單純的正規表達式（Regular Expression）抓取尾端的價格數字（例如 `/\$(\d+)/`）；然而，若要提取完整的晶片型號或搭機條件，Regex 極易因原價屋小編臨時增減括號、活動標籤（如「獨家贈送滑鼠墊」、「限搭任一主機板」）而破碎。現代開源工具因此演進為結合正則預過濾與輕量本機 LLM（如 LLaMA / Ollama）進行自動化屬性對齊。
